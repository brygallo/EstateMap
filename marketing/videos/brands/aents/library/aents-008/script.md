# Video 008: Estás creando software con inteligencia artificial

Estado: `planificado`

## Estrategia

- Público: emprendedor
- Etapa: descubrimiento
- Objetivo: Enseñar cómo se dirige a una inteligencia artificial para que construya software sostenible, y abrir conversación con quien esté levantando un proyecto así y reconozca que ya se le está yendo de las manos
- Conversión: contact_request
- Pilar: Software a medida
- Serie: Conoce Aents
- Concepto: Escribir código no es construir software
- Promesa: Doce decisiones concretas que separan un código generado en minutos de un sistema que se puede sostener, y la señal para saber cuándo el proyecto ya necesita ayuda
- CTA: Cuéntanos qué estás construyendo
- Hipótesis: Quien está construyendo con inteligencia artificial no responde a un argumento sobre calidad, pero sí reconoce su propio proyecto fallando: enseñar cada error en pantalla y su corrección convierte esa incomodidad en una consulta
- Portada: Construyes software con IA

## Voz completa

¿Estás creando una página web, una aplicación o un sistema completo usando inteligencia artificial? Entonces esto es para ti. Porque hay una diferencia enorme entre lograr que escriba código, y lograr que construya buen software. Primero: no empieces diciendo solamente créame una aplicación. Una inteligencia artificial programa mucho mejor cuando entiende qué estás construyendo. Explícale quién va a usarlo, qué problema resuelve, qué puede hacer cada usuario y qué nunca debería ocurrir. Segundo: no le pidas el sistema completo en un solo mensaje. Ver aparecer cientos de archivos impresiona, hasta que buscas dónde está el error. Divide: primero la arquitectura, después el acceso, después una funcionalidad. La pruebas, la corriges y recién ahí sigues. Tercero: define las reglas del negocio antes de pedir código. Imagina un sistema de citas. No basta con decir necesito reservar citas. ¿Qué pasa si dos personas piden el mismo horario? ¿Quién puede cancelar, y hasta cuándo? Eso pesa mucho más que el color de un botón. Y este es el error más importante. Ejecutas la aplicación, presionas el botón, funciona, y piensas que ya está. Pero funcionar en el caso perfecto solo demuestra eso. ¿Qué pasa sin internet? ¿Si el usuario presiona dos veces? ¿Si intenta algo para lo que no tiene permiso? Otro consejo: no aceptes automáticamente todo el código que genera. Pregúntale por qué creó ese archivo, por qué usó esa librería, si hay una forma más simple. Úsala también para discutir decisiones técnicas, no solo para escribirlas. Presta atención a las librerías. Puede recomendarte una dependencia simplemente porque conoce una solución que la usa. Antes de instalarla pregúntate si de verdad la necesitas, si sigue mantenida y si estás sumando algo enorme para resolver algo pequeño. Y esto es especialmente importante: no dejes la seguridad para el final. El acceso, los permisos, la validación y las credenciales se deciden desde la arquitectura. Nunca asumas que por esconder un botón en la pantalla alguien ya no puede hacer esa acción: eso se comprueba en el servidor. Ten cuidado con lo que compartes con cualquier herramienta de inteligencia artificial. No pegues contraseñas, claves de acceso, datos privados de tus clientes ni archivos internos sin entender antes cómo funciona esa herramienta y qué permite tu organización. Después de pedirle que implemente algo, pídele que lo pruebe. Que intente romper lo que acaba de construir. Y cuando aparezca un error, no le digas solamente arréglalo: haz que primero explique por qué ocurrió. Tapar el síntoma crea otro problema más abajo. Y por favor, usa control de versiones. Puede cambiar muchísimo código en segundos, hasta que toca veinte archivos y rompe algo que ayer funcionaba. Guarda cambios pequeños, deja un punto estable antes de una modificación grande y asegúrate de poder volver atrás. Aparece otro problema: como generar código es facilísimo, generamos demasiado. Una función nueva, y otra que hace casi lo mismo. Seis semanas después ni tú ni la inteligencia artificial entienden el proyecto. Cada cierto tiempo detente, elimina lo duplicado y simplifica. Y recuerda algo fundamental. Puede saber muchísimo de programación, pero no conoce tu negocio. Puede crear un botón que diga aprobar, pero no sabe quién debería aprobar. Bien usada acelera todo; el problema empieza cuando le entregamos también las decisiones. Así que dale contexto, divide el problema, define las reglas, revisa el código, piensa en la seguridad desde el principio y mantén tu proyecto ordenado. La velocidad sirve solamente si sabes hacia dónde estás construyendo. Y si tu proyecto está creciendo, en Aents desarrollamos software a medida. Cuéntanos qué estás construyendo. Aents. ## Caption

Si estás creando una página web, una app o un sistema completo con inteligencia artificial, esta clase es para ti.

Una IA puede generar en minutos lo que antes tomaba horas. Pero hay una diferencia enorme entre lograr que escriba código y lograr que construya buen software.

Dentro: dale contexto antes de pedir, divide el proyecto en partes, define las reglas del negocio antes del código, no confundas el caso perfecto con un producto terminado, revisa lo que genera, cuida las dependencias, piensa la seguridad desde la arquitectura, no pegues secretos en cualquier herramienta, haz que pruebe su propio trabajo, usa control de versiones y mantén el proyecto ordenado.

Y lo que ninguna herramienta reemplaza: tu negocio.
